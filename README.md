## 这是什么

一个**自建网盘**，适合这样的场景：

- 你想把自己的一堆文件放到云上，用**自己的域名**访问，数据只在你的 Cloudflare 账号里；
- 你不想买服务器、不想装 Docker、不想维护数据库；
- 你希望部署方式是"**复制一个文件 → 粘贴 → 完成**"，而不是"clone → install → build → migrate"；
- 你担心免费额度被写爆，希望程序自带配额保护与可视化统计。

它同时也是一个**完整的网盘**：上传下载、目录管理、分享链接、相册、标签与筛选、回收站与版本、备份恢复、WebDAV、PWA、移动端手势——都在这一个文件里。

## 为什么是"单文件"

这不是偷懒，而是一个明确的取舍：

| 好处 | 代价 |
|---|---|
| 部署 = 复制粘贴，无供应链风险，无构建链断裂 | 文件很大（约 1.3 万行），搜索与阅读成本高 |
| 不会出现"改了前端忘了重新构建"的经典事故 | 前后端耦合，改动必须更谨慎 |
| 一份文件就是全部状态，便于审计（安全审查只需看一个文件） | 不能用现代前端框架的便利 |
| 任何时间点的版本都能直接跑起来 | 因此回归测试与断言纪律要求更严（见 [CONTRIBUTING.md](./CONTRIBUTING.md)） |

**如果你需要拆分、引入依赖或加构建步骤，请先开 Issue 讨论**——这属于会改变项目定位的变更。

## 架构

```
                                浏览器 / PWA / WebDAV 客户端
                                              │
                                   HTTPS（自建域名 + CNAME）
                                              ▼
                    ┌──────────────────────────────────────────────────┐
                    │            Cloudflare Worker（_workers.js）       │
                    │                                                  │
                    │  路由层  →  鉴权（会话 / 无状态会话 / 只读令牌）   │
                    │         →  风控（IP·CIDR / 国家 / UA / 限流）      │
                    │         →  锁定目录检查（guard）                  │
                    │                                                  │
                    │  业务层  →  文件 · 分享 · 相册 · 标签 · 检索       │
                    │         →  备份 · 定时任务 · 目录规则 · 审计       │
                    │                                                  │
                    │  视图层  →  内嵌 SPA（HTML + CSS + JS 同文件）     │
                    │         →  公开页（分享 / 相册 / 上传）+ Service  │
                    │            Worker（离线缓存 + 分享即上传）        │
                    └───────┬──────────────────┬───────────────────────┘
                            │                  │
                 ┌──────────▼───────┐  ┌───────▼─────────┐  ┌──────────────────┐
                 │  R2  绑定 DRIVE  │  │ KV  绑定 STORE  │  │ DO  绑定 DIR(可选)│
                 │  文件本体         │  │ 目录元数据/会话  │  │ 目录索引加速      │
                 │  .versions/ 版本  │  │ meta:* 配置/统计 │  │ 类名 DirStore     │
                 │  .trash/ 回收站   │  │ 各类索引 + TTL   │  │ 不绑自动回退 KV   │
                 │  .chunks/ 分片    │  │                 │  │                  │
                 │  .thumb/ .backup/│  │                 │  │                  │
                 └──────────────────┘  └─────────────────┘  └──────────────────┘
```

要点：

- **R2 里的点号前缀目录是内部对象**（`.versions/` `.trash/` `.chunks/` `.thumb/` `.backup/`），不会出现在文件列表，也不能通过分享/相册/WebDAV 读到；
- **KV 是元数据唯一真相源**，DO 只是加速层；DO 实例被回收或被清空时会自动从 KV 重新播种；
- **所有上限都可在站点配置面板里调**，无需重新部署。

## 功能一览

### A · 安全

| 功能 | 说明 |
|---|---|
| 二次验证 TOTP | 兼容任意验证器 App；启用时下发 8 个一次性备用码；登录强制校验 |
| 会话管理 | 会话 7 天，可列出登录设备并逐个/批量注销；改密即全体失效 |
| 无状态会话兜底 | KV 写入额度用尽时改用 HMAC 签名会话（`s2.` 前缀），仍可登录；改密即失效 |
| 只读访问令牌 | 可签发 `ro` 令牌给脚本/第三方：可读不可写（写接口 403） |
| 限流 | 读/写分桶令牌桶（默认 150/30 次每分钟）；登录另有 IP + 用户名双维度计数（5 次/5 分钟） |
| 风控 | IP 黑白名单（支持 CIDR）、国家黑白名单、UA 黑白名单（站点与分享两级） |
| 锁定目录 | 给任意目录设密码（含根目录整体上锁）；锁定子树在搜索/查询/复制/删除中一并受保护 |
| 限时签名直链 | 生成带签名与过期时间的下载链接，可外发给不支持 Cookie 的场景 |
| 审计日志 | 登录、上传、下载、删除、移动、恢复、配置变更等全程留痕，支持筛选与 CSV 导出 |
| 输入闸门 | 文件名净化、路径长度上限、KV 键长度校验、颜色值校验、HTML 属性转义、SSRF 检查（抓取远程 URL 时） |
| 通知 | 新设备/新地区登录提醒、评论提醒，可推送到 Webhook |

### B · 传输

| 功能 | 说明 |
|---|---|
| 上传队列 | 多文件并发上传（1–6 可调）、暂停/继续/取消/重试、逐文件进度与状态 |
| 分片上传 | >5MB 自动切片（5MB/片），支持 multipart 组装，装配后校验大小 |
| 断点续传 | 中断的任务被记录，刷新或重开页面后可一键恢复；孤儿分片由定时任务回收 |
| 秒传 | 客户端算内容哈希，命中则直接在目标目录落一份记录，不重复上传 |
| 拖拽上传 | 支持整个文件夹拖入（保留相对路径）；拖拽时出现细提示条 |
| 剪贴板 | 站内 ⌘C/⌘X/⌘V 复制剪切；也可直接粘贴系统剪贴板中的文件上传 |
| 站内复制 | 服务端递归复制目录（含缩略图与用量同步） |

### C · 分享协作

| 功能 | 说明 |
|---|---|
| 文件分享 | 生成 `/s/<token>` 页面：预览、下载、二维码 |
| 目录分享 | 目录分享页可浏览子目录、打包下载整个文件夹 |
| 细粒度权限 | 允许下载 / 仅预览、一次性下载（下载即失效）、允许访客留言 |
| 访问控制 | 分享级 IP·CIDR、国家、UA 限制；独立访问密码；访问次数上限与有效期 |
| 自定义短链 | `/s/<自定义别名>`（2–32 位字母数字下划线），可随时更换或清除 |
| 访问统计 | 浏览量、下载量、最近访问明细（IP/国家/浏览器/设备）；写盘有节流，不耗额度 |
| 访客留言 | 站内与访客共用一套评论；可开关；新留言可推 Webhook |
| 分享外观 | 自定义标题、描述、主题色、给访客的提示语 |
| 流式打包 | 边读边写 ZIP（数据描述符），上限 2000 文件 / 2GB；分享打包 500 文件 / 512MB |
| 公开上传 | `/upload` 页接收匿名上传（可配置目标目录、大小上限、Turnstile 人机验证）；也可生成限时上传链接 `/u/<token>` |

### D · 媒体

| 功能 | 说明 |
|---|---|
| Office 预览 | docx / xlsx / xls / csv / ods 在线预览（按需加载解析库，输出经净化）；pptx 等给出下载提示 |

| 相册 | 公开只读相册 `/a/<id>`：可选密码、分页加载、原图下载、EXIF 拍摄时间分组、GPS 链接到地图 |
| 缩略图 | 图片自动生成缩略图（R2 内部前缀），随文件删除而清理 |

### E · 检索与组织

| 功能 | 说明 |
|---|---|
| 高级筛选 | `/api/query`：名称、类型、扩展名、大小区间、日期区间、标签（任一/全部）、仅收藏、是否递归、排序、分页 |
| 标签体系 | 标签计数与颜色、重命名/合并（批量改写文件标签）、批量增删、多标签 AND/OR 筛选、按类型或年月自动打标签 |
| 收藏分组 | 收藏可分组管理（新建/重命名/删除/加入/移出），与收藏本身互不干扰 |
| 最近访问 | 记录最近打开的文件，可一键回访 |
| 重复文件 | 按内容哈希找重复；相似图片按感知哈希找近似 |
| 元数据导出导入 | 子树内文件的标签/备注/收藏/大小/时间导出为 JSON 或 CSV；导入时只匹配已存在文件，支持合并或覆盖 |
| 批量操作 | 多选后批量重命名（支持 `{n}` 序号）、移动、下载、打包、分享、删除 |

### F · 运维与配置

| 功能 | 说明 |
|---|---|

## 快速开始

### 前置条件

1. 一个 Cloudflare 账号（**免费版即可**，但 Durable Object 免费版可用性以 Cloudflare 当前政策为准；不绑 DO 也能跑）；
2. 一个 R2 存储桶（内容存这里）；
3. 一个 KV 命名空间（元数据存这里）。

### 方式一：控制台粘贴（最快）

1. Cloudflare 控制台 → **Workers & Pages → 创建 Worker**；
2. 打开本仓库的 `_workers.js`，**Ctrl+A 全选 → Ctrl+C**；
3. 回到 Worker 编辑器，全选默认模板 → **Ctrl+V 粘贴 → Deploy**；
4. 进入 **Settings**，添加绑定与环境变量（见下一节）；
5. 打开你的 Worker 域名 → 看到登录页 → 输入 `DRIVE_PASSWORD` 登录。

### 方式二：wrangler（便于版本管理）

```toml
# wrangler.toml
name = "cf-kvr2-networkcloud"
main = "_workers.js"
compatibility_date = "2025-01-01"

# 文件内容
[[r2_buckets]]
binding = "DRIVE"
bucket_name = "your-bucket-name"

# 元数据
[[kv_namespaces]]
binding = "STORE"
id = "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"

# 可选：目录索引加速（不绑会自动回退 KV）
[[durable_objects.bindings]]
name = "DIR"
class_name = "DirStore"

[[migrations]]
tag = "v1"
new_sqlite_classes = ["DirStore"]   # 用 SQLite 后端；老账号也可用 new_classes

# 可选：定时任务（回收站清理 / 分片回收 / 自动备份 / 自定义任务）
[triggers]
crons = ["17 3 * * *"]

[vars]
DRIVE_PASSWORD = "换成你自己的强口令"
```

```bash
npx wrangler deploy
```

> ⚠️ 绑定名必须**完全一致**：`DRIVE`（R2）、`STORE`（KV）、`DIR`（DO）。名字不同会导致启动即报错或功能缺失。

### 首次部署自检（6 步）

1. 访问 `https://<你的域名>/api/version` → 应看到 `{"version":"v5.2.0","ui":"flat-1","bindings":{"store":true,"drive":true,"dir":false}}`
   - `store/drive` 必须是 `true`；`dir:false` 表示未绑 DO（功能正常，只是回退 KV 模式，稍慢）；
2. 登录页输入错误密码 → 应返回「Wrong password」；输入正确口令 → 进入**概览页**；
3. 上传一个文件 → 队列条变绿 → 刷新后仍在 → 预览一次、下载一次；
4. 创建分享链接 → 无痕窗口打开 `/s/<token>` 能预览、能下载；
5. 打开当前页 ⋯ → **运维与配置 → 健康检查**：三项全绿，并查看「防爆面板」的 R2 采样与 KV 写入数；
6. 页面底部状态条应显示 `vX.Y.Z · <构建号>`——这是判断"线上是不是最新版"的最快方式。

## 防 KV / R2 爆

这一节是本项目的核心设计约束——所有功能都必须在"免费额度"下安全运行。

| 维度 | 机制 | 默认 |
|---|---|---|
| **KV 读** | 隔离级缓存 `kvCached`：会话 10s、目录锁列表 20s、配置 30s、标签计数 60s、仪表盘 30s | `SESSION_CACHE_SEC=10` |
| **KV 写** | 每分钟写预算 + 每日遥测预算 + 遥测内存缓冲合并落盘（15 秒窗口）+ 收藏/最近合并写 | `KV_BUDGET_PER_MIN=600`、`TELEMETRY_MAX_PER_DAY=500` |
| **KV 体积** | 单值 8MB、单目录 20000 条、路径 400 字符、键 480 字符、备注 64KB、标签 8KB | `KV_VALUE_MAX`、`MAX_DIR_ITEMS`、`PATH_MAX` |
| **KV TTL** | 秒传索引 30 天、版本索引 90 天、会话、登录计数 10 分钟、解锁记录、评论 400 天、备份索引 | `HASH_TTL_DAYS`、`VERSIONS_TTL_DAYS` |
| **R2 体积** | 版本数 ≤5、单版本 ≤64MB、回收站 30 天自动回收、分片 24 小时回收、备份 14 份且总占用 ≤200MB | `VERSIONS_MAX`、`TRASH_DAYS`、`CHUNK_GC_HOURS`、`BACKUP_KEEP` |
| **大目录** | 列表分页渲染 + 虚拟滚动、查询结果上限 3000、媒体清单上限 2000、打包流式写入 | — |
| **观测** | `GET /api/health` 的 `guard` 字段：缓存条目数、近一分钟写入数、预算、缓冲中遥测条数、R2 对象与内部占用采样 | — |

**降级策略**：额度用尽时，**遥测类写入（日志/最近/下载明细）自动暂停**（只驻内存），而登录、目录元数据等关键写入仍然放行——宁可统计不准，不可用不了。

## 性能

用内存版 R2/KV/DO 对每类请求做了操作计数与延迟测量（给 DO 调用加 1.5ms 人造延迟以模拟真实往返），并按测量结果优化：

| 请求 | 优化前 | 优化后 |
|---|---|---|
| `GET /api/list`（任意目录） | DO 往返 2 · **DO 存储写 1** | DO 往返 **1** · 存储写 **0** |
| `GET /api/usage` | DO 2 · 写 1 | DO **1** · 写 **0** |
| `GET /api/preview`、`/api/thumb` | DO 1 · 写 1 | **DO 0 · 写 0** |
| `POST /api/rename` | DO 1 · 写 1 | **DO 0 · 写 0** |
| `POST /api/mkdir` | DO 5 · stGet 5 · 写 2 | **DO 1 · stGet 1 · 写 1** |
| `GET /api/tree`（43 个目录） | 584 ms（串行） | **65 ms（按层并行，约 9×）** |
| `GET /api/query?deep=1`（43 个目录） | 517 ms | **59 ms（约 8.8×）** |
| `GET /api/dashboard` | DO 1.3 | DO **0.3**（30 秒缓存） |

主要手段：① 限流器从 DO 改为 isolate 内存令牌桶（省掉每请求一次 DO 往返 + 一次存储写）；② 目录遍历**按层并行预取**（`DIR_PREFETCH`）；③ 目录写操作由 DO 直接返回最新列表，KV 镜像不再二次回读；④ 会话/配置/标签计数等读缓存。

## 安全模型

| 层 | 措施 |
|---|---|
| 传输 | 强制 HTTPS（Cloudflare 默认）；HTML 响应 `no-cache` + `CDN-Cache-Control: no-store`，避免旧页面被边缘缓存 |
| 认证 | 口令哈希（加盐）；会话 7 天；无状态会话 HMAC 签名（96 位截断、常量时间比较、可被改密立即吊销）；只读令牌 |
| 二次验证 | TOTP（SHA-1/6 位/30 秒）+ 8 个一次性备用码（仅存哈希） |
| 授权 | 目录密码（含根锁）；分享级权限；只读令牌写拦截；锁定子树在遍历类接口中一并过滤 |
| 滥用防护 | 多维度限流（读/写/登录 IP/登录用户名）；IP·国家·UA 风控；公开上传可挂 Turnstile |
| 输入安全 | 路径规范化与长度上限、文件名净化、属性转义、KV 键校验、远程抓取 SSRF 检查、预览文件强制安全响应头 |
| 数据保护 | 内部对象不可通过分享/相册/WebDAV 读取；回收站与版本以新 key 保存（避免同名重传后被误删）；备份快照不含 TOTP 密钥 |
| 可观测 | 审计日志 + CSV 导出；登录/评论 Webhook 通知；健康检查与防爆面板 |

**安全建议（部署清单）**

- [ ] `DRIVE_PASSWORD` 使用强口令，并考虑单独设置 `URL_SIGN_SECRET`；
- [ ] 开启二次验证（⋯ → 运维与配置 → 二次验证），保存好备用码；
- [ ] 若对外开放上传页，配置 `TURNSTILE_SITE_KEY` + `TURNSTILE_SECRET`；
- [ ] 按需配置 `IP_ALLOW` / `COUNTRY_ALLOW` 收敛访问来源；
- [ ] 定期查看「登录设备」与「活动日志」；
- [ ] 定期做一次备份并**实际演练一次恢复**（备份没演练过等于没有）。

漏洞报告请走 [`SECURITY.md`](./SECURITY.md)，**不要**先开公开 Issue。

## 运维：备份、定时任务、目录规则、审计

### 备份与恢复

- 入口：⋯ → **数据 → 备份与恢复**；
- 快照内容：目录树、标签、备注、分享链接、上传链接、目录密码、收藏、最近、用量统计；
- **不含文件本体**（文件已在 R2 中，无需重复备份）；**不含二次验证密钥**（避免密钥随快照外泄）；
- 增量快照只记录变化目录，恢复时自动沿链合并；恢复前可先「差异」预览会新增/删除/变更哪些内容；
- 恢复需要管理员口令，**不可撤销**，建议恢复前先手动备份一次。

### 定时任务（Cron）

配置 `[triggers] crons = [...]` 后，每次触发会执行：① 回收站过期清理；② 用户自定义任务；③ 未完成分片回收；④ 内部对象（孤儿缩略图/版本）回收；⑤ 每日自动备份；⑥ 遥测缓冲落盘。

自定义任务在 ⋯ → 运维与配置 → 定时任务 里创建，支持三种类型：**TTL 过期清理**（可进回收站或彻底删除）、**清空目录**、**自动归档**（按月份移动到 `archive/YYYY/MM/`）。单次最多处理 500 个条目，也可手动点 ▶ 立即运行。

### 目录级规则

给指定目录设：文件数上限、容量上限（MB）、单文件上限（MB）、扩展名白/黑名单。普通上传、分片上传、上传链接、公开上传、WebDAV 导入都会遵守。

### 审计与通知

- 审计日志记录登录、上传、下载、删除、移动、恢复、配置变更等，支持关键词/类型/时间筛选与 CSV 导出；
- Webhook 可推送：新设备/新地区登录、新评论、关键操作（详见「通知」面板，可填 Secret 做签名校验）。

## 常见问题 FAQ

**Q1：一定要绑定 Durable Object 吗？**
不。`DIR` 是可选的加速层。不绑定时目录索引走 KV，功能完全一致，只是并发改写与大目录遍历会慢一些。绑定后 DO 存储放不下的大目录会自动回退 KV 合并路径。

**Q2：免费版够用吗？会不会被限流？**
代码就是按免费额度设计的：默认每日遥测写预算 500（KV 免费额度 1000 写/天的**一半**），并有多级缓存与预算控制。正常个人使用（每天几十次上传/浏览）通常远低于额度。若触发限制，遥测类写入会先降级，主功能不受影响。

**Q3：能用自己的域名吗？**
可以。在 Cloudflare 里给 Worker 配置 Custom Domain（或 Route），再把域名解析接过来即可；更新 `CNAME` 文件如果用于 GitHub Pages 展示页，与 Worker 域名互不影响。

**Q4：支持多大的文件？**
默认单文件上限 500MB（可在配置面板调 `maxUploadMB`）；>5MB 自动走分片上传。上限受 Cloudflare 请求体限制与你的套餐影响。

**Q5：备份包含文件内容吗？**
不包含，只含元数据。文件本体在 R2 里，删了就没了——所以**不要用"备份"来替代文件本身的备份策略**；重要文件建议在 R2 之外另存一份。

**Q6：目录密码、根目录上锁是怎么工作的？**
目录密码记录在 KV，解锁状态绑定当前会话（有效期 10 分钟）。锁定子树在列表、搜索、查询、复制、移动、删除等所有路径上都会被过滤或拒绝——包括分享页面。

**Q7：分享链接怎么做得更安全？**
组合使用：访问密码 + 有效期 + 访问次数上限 + 一次性下载 + 禁止下载（仅预览）+ IP/国家/UA 限制 + 自定义短链。敏感文件还可先加密上传（`.enc` 密文，密钥在客户端）。

**Q8：WebDAV 能挂载吗？**
可以，地址 `https://<域名>/dav/`，用户名任意、口令为管理员口令。Windows「映射网络驱动器」、macOS「连接服务器」、Linux `davfs2` 均可。注意目录 MOVE/COPY 暂不支持（返回 501），大目录遍历可能较慢。

**Q9：怎么确认线上是不是最新版？**
看页面底部状态条（形如 `v5.2.0 · flat-1`）或访问 `/api/version`。两者都带**界面构建号**，是用来看"部署有没有生效"的。

**Q10：升级会不会丢数据？**
不会：数据都在 R2/KV 里，Worker 只是代码。升级流程＝粘贴新代码 → Deploy。但**破坏性变更**（绑定改名、KV 结构变化）会在发布说明里标注，请先读再升。

**Q11：怎么回滚？**
保存上一版代码（Git 或本地副本），重新粘贴部署即可。数据层无需回滚——这也是本项目坚持"读侧宽松解析、老数据可读"的原因。

**Q12：为什么界面是"文件优先 + 密集列表"？**
因为这是个人网盘最主要的用途：快速找到文件。概览（统计与快捷入口）作为落地页存在，但工具栏与列表都按"高频操作一步可达"来排布——11 个常用按钮常显，长尾进 ⋯ 与 ⌘K。

## 已知限制与取舍

诚实列出（这些不是 bug，是明确的取舍）：

| 项 | 现状 | 原因 |
|---|---|---|
| CSP / SRI | 未启用 | 单文件内联脚本样式极多，加严格 CSP 需要大量 nonce/hash 改造且易打断应用；Office/PDF 预览按需加载 CDN 资源，SRI 会随上游版本失效 |
| WebDAV 目录 MOVE/COPY | 返回 501 | 与站内 `/api/move`、`/api/copy` 语义不同（跨挂载点/权限），错误实现比不支持更危险 |
| WebDAV `Depth: infinity` | 按 1 处理 | 避免一次 PROPFIND 打爆递归与 KV 读配额 |
| 内容寻址去重（CAS） | 未实现 | 已有"秒传"按内容哈希命中；真正的 CAS 需重构 20+ 处读路径与 GC，收益与风险不成比例 |
| 无状态会话 | 不可提前吊销 | KV 写入不可用时才签发；不写 KV 所以不出现在设备列表，改密或等 TTL 才失效（界面会提示） |
| 大目录（>20000 项） | 拒绝写入 | 防止 KV 值超限导致元数据静默丢失；请拆分目录 |
| 单文件规模 | 约 1.3 万行 | 换取"拷走即用"；代价是阅读成本，因此测试与文档要求更严 |
